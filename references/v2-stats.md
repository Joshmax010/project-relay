# 卷三 3.4：成本实测与阈值调优（计数口径、报告、调优规程、保险丝）

实现：`scripts/relay_stats.py`（计数、报告、调优、保险丝）+ `scripts/relay_flow.py`
接线（采集/汇总/接手三处）+ `relay stats` CLI。计划依据：计划分卷 03 §3.4、
S1（三刻度）、S7（注入预算与三层检索）。

## 1. 位置规则：统计数据住在仓外

统计行住在 `<store-root>/stats/<key>-<slug>/`（由仓目录的
`<root>/projects/<name>` 布局推导；非常规布局回退到仓内 `stats/`）。
这样设计同时满足两条硬约束：

- **每次接手都记**（§3.4 要求），又不改动仓目录树——resume 的 1–3、5 段
  严格只读、仅第 4 段可写的契约原样成立，零写测试无需改动。
- **绝不上报**：同步包只读仓目录本身，统计连仓都没进，换设备也带不走；
  校验清单只覆盖 `archive/`，统计也不影响档案完整性。

## 2. 计数口径

### 2.1 采集行（`capture.jsonl`，零 LLM）

每次采集一行：时间（ISO + epoch）、工具、采集条目数（去重为 0）、
工作区指纹变化文件数（降级条目为 null）、采集耗时（秒）、
deduped/degraded 标志。采集本身不调模型，故无 token 字段。

### 2.2 汇总行（`summarize.jsonl`）

每次汇总一行（含 noop/降级/成支行，报告算均值时只取有效行）：
触发源 `source` + 触发刻度 `trigger`（显式值优先；缺省时按源映射：
resume-backfill→handoff，manual/accept→manual，pack→pack，其余→other；
milestone/volume/time 三刻度目前只能由显式 `--trigger` 传入，因为现有
调用方不推导刻度）、新原料条数与估算 tokens（条目正文字符/1.5）、
旧摘要 tokens（汇总前状态管理块字符/1.5）、LLM 调用次数与 in/out tokens、
拼装层与 LLM 层字符数、档案净增量 tokens（四档案文件字符增量/1.5）。

- **拼装 vs LLM 划分**：无模型调用时（确定性占位或接手自动纠正文本），
  全部语义文本计入拼装层；调用方传入语义文本时，状态管理块计入拼装层、
  传入文本计入 LLM 层。接手自动纠正文本是工具生成的（零模型调用），
  故计入拼装层——保险丝降级时它也不被丢弃。
- **实测 vs 估算**：调用方传 `llm_usage={calls, input_tokens, output_tokens}`
  时记为实测；传入语义文本但无用量时记一次估算调用（输入 = 新原料 +
  旧摘要估算，输出 = 语义文本估算）；纯拼装记零调用且为实测（工具可证明
  自己没调模型）。报告里实测与估算分开列，不混算。

### 2.3 接手行（`handoff.jsonl`）

每次接手一行：注入 tokens 分层实测（索引层 = 导航 + 目标 + 状态顶部；
时间线层 = 待办；全文层 = 实际纳入的决策/教训，全文或仅标题，裁剪后
的纳入量为准；均为字符/1.5 估算）、对账差异分类计数（基线后改动文件数、
缺失文件数、分支不一致、暂存区不符、校验清单不符）、补汇总次数、
上次汇总 LLM tokens、**单次接手总成本 = 上次汇总 LLM + 本次注入**。

- **上次汇总的口径**：接手开始时最近的汇总行；本次接手触发的补汇总
  计入下一次接手的上次汇总，不计入本次。否则补汇总的成本会被算两次。
- **漏记率代理**：对账差异中“基线后改动文件”类占比。它是代理指标，
  不是漏记率本身——对账差异还含过期类（缺失文件、分支漂移），报告里
  按代理标注，不写成实测漏记率。

## 3. 报告：`relay stats [--weeks N]`

按周/按项目输出本地报告：各计数均值与 P95（P95 用 nearest-rank 法；
采集耗时均值保留 3 位小数，否则亚秒耗时全被四舍五入成 0）、三刻度
各自的触发占比（全部占比 + 刻度内占比）、周成本曲线（汇总 LLM +
接手注入）、规则生成的调优建议、保险丝状态。报告首段直接回答计划的
三个问题：每接力一次平均花多少 tokens、其中 LLM 汇总占多少、
三刻度谁最常触发。

调优建议规则（全部带证据，不凭空出现）：时间刻度从未独立触发且改动量
总先到 → 时间阈值可放宽；改动量占刻度触发八成以上 → 上调改动量阈值；
接力成本中 LLM 汇总占七成以上 → 上调汇总阈值或下调注入预算（一次只动
一个）；保险丝触发 → 先查触发逻辑；月度软上限告警 → 仅提示上调上限；
窗口无数据 → 明说暂无依据。

## 4. 调优规程：`relay stats --tune-knob K --tune-value V [--tune-note T]`

旋钮（一次只动一个，一次调用只改一个配置键）：改动量文件数
`volume_files`（→threshold_files ≥1）、改动量行数 `volume_lines`
（→threshold_lines ≥1）、时间天数 `time_days`（≥1）、注入预算
`inject_budget`（→inject_budget_tokens，500–8000，S7 护栏）、预压缩采样
上限 `precompress_sample_cap`（→precompress_sample_cap，None 表不采样）。

- **护栏**：单次变动不超过原值的 ±50%（从 None 首次设值除外，无步长可量）；
  超护栏、越硬范围、未知旋钮、非整数一律拒绝，配置与决策行不落盘。
- **决策记录**（`tuning.jsonl`）：每次调整一行，含调整前两周的接手均值与
  次数；评估时补后两周对照。`relay stats --eval-tune` 在后窗口满两周后
  （或测试用强制）评估：后均值严格低于前均值且两边都有接手数据才算改善；
  任一边无数据则保持待评估，不计入失败。
- **回退**：连续两次评估无改善 → 旋钮回到 streak 开始前的值，写一条
  rollback 行，并把结论追加进 `archive/lessons.md`（新 L 编号，附两次
  调整的旧→新值与 tuning 行引用），随后刷新校验清单。评估时跳过已回退
  的 streak，不重复回退。

预压缩采样上限的语义：设值后 precompress 只取最近 N 条 pending 原料
算 digest/numbers；默认值 None 保持旧行为不变。采样会改变汇总输入，
故只在用户显式调优时生效，报告与文档均明示这一点。

## 5. 保险丝：周飙升自动降级，月度软上限只告警

- **周飙升保险丝**：本周汇总 LLM tokens ≥5000 且超上周 3 倍时触发
  （上周无数据则无基线，不触发；5000 地板防小项目因一次汇总误触发）。
  触发后汇总降级为只拼装：调用方传入的语义文本被丢弃，汇总行标 fused；
  工具生成的自动文本（零模型调用）不受影响；接手输出头部以保险丝告警
  横幅先行（与带病横幅同机制）。保险丝在周成本回落到条件以下时自动
  清除；`relay stats --clear-fuse` 可人工清除（下次评估仍满足条件会
  重新触发）。
- **月度软上限**：配置 `monthly_llm_token_cap`（默认 None），当月汇总 LLM
  超上限时只在报告与保险丝状态里告警，永不降级、永不拦截汇总。
- **实现位置**：每次汇总前评估保险丝并持久化状态；接手只做纯计算
  （不写状态），接手读路径保持零写。

## 7. 偏离与边界

- **统计住仓外**（见 §1）：为保 resume 零写契约而做的有意设计，不是
  计划原文的写法；计划只说“本地统计”，未定落点。
- **触发刻度来源**：milestone/volume/time 三类目前只接受显式传入
  （`summarize --trigger` 或 API 参数）；现有调用方（scales 建议、pack、
  接手兜底）不推导刻度，故报告里 scale 类行在显式传入前为空——这是
  诚实的缺口，不是统计 bug；接 scales 触发判定到汇总调用是后续接线工作。
- **token 均为估算**（除调用方上报的用量外）：字符/1.5 是 S7 定下的口径，
  报告永远标注实测/估算分离。
- **保险丝只看汇总 LLM**：接手注入 tokens 不计入保险丝（注入是只读
  消费，不产生模型调用费用）；月度上限同理。
