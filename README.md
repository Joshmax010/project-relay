# Project Relay · 项目接力

**让项目携带自己的记忆，让下一个 Agent 接得住。**

Project Relay 是一个基于 Markdown 的项目记忆与交接协议，以及用于初始化和维护该协议的 Agent Skill。适用于软件、小说、研究和其他项目。

## 快速开始

将本仓库下载或克隆到一个独立的 `project-relay` 文件夹。不要用某个旧项目的 `.agent` 充当新项目模板。

### 方式一：让 Agent 执行

向具备文件读写能力的 Agent 提供本仓库并说：

> 阅读 project-relay/SKILL.md，为我指定的项目初始化 .agent。先了解现有资料，再填充项目事实和交接记录。

支持 Agent Skills 的工具可把整个仓库目录作为技能包安装，具体安装位置由工具决定。无需为了使用核心协议安装平台专属服务。

### 方式二：生成骨架

需要 Python 3，仅使用标准库：

```bash
python3 /path/to/project-relay/scripts/init_project.py /path/to/your-project
```

Windows 可使用 `python`，路径含空格时加双引号。目标项目目录须已存在。脚本只创建缺失文件，不覆盖旧记录；生成骨架后，仍需让 Agent 阅读项目并完成初始化。没有 Python 时，Agent 可依据 Skill 复制模板并逐项填充。

### 后续接手

> 先阅读 .agent/agent.md，按索引了解项目现状，然后继续我的任务。每完成一个有意义的步骤就更新记录。

## 项目文件

| 路径 | 用途 |
|---|---|
| `.agent/agent.md` | 执行协议、角色、维护职责与按需阅读索引 |
| `.agent/human.md` | 人如何让 Agent 接手、收尾与检查 |
| `.agent/project.md` | 目标、范围、约束与验收标准 |
| `.agent/state.md` | 精简当前状态、阻塞、下一步 |
| `.agent/structure.md` | 架构、章节、研究路线和资料入口 |
| `.agent/decisions.md` | 决策、理由、备选项和替代关系 |
| `.agent/lessons.md` | 教训、证据和适用条件 |
| `.agent/changelog.md` | 项目层面的变更记录（逐步执行过程仍在 sessions） |
| `.agent/sessions/` | 按会话保存执行过程与步骤检查点 |
| `.agent/conversations/` | 原始聊天、部分原文或明确标注的交接摘要 |

## 工作流程

1. **接手**：读入口、项目定义、当前状态及最近交接，核对真实产物。
2. **计划**：明确当前任务和验收标准，按需检索决策与教训。
3. **执行**：重要改动前记录意图；有意义步骤完成后保存结果及证据。
4. **验证**：区分验证通过、失败和未验证，采用符合项目类型的方法。
5. **更新**：刷新状态，记录关键决策、失败尝试、可复用教训和项目层面变更。
6. **交接**：保存能获取的原文；否则写详细摘要并声明覆盖范围，给出下一步。

完整规则见 [Agent 协议模板](assets/template/agent.md)。

## 兼容性与边界

- 核心是普通 Markdown 和相对路径；无需特定模型、API、数据库或联网服务。
- `SKILL.md` 使用 `name` / `description` 元数据；`agents/openai.yaml` 是可选平台元数据，其他工具可忽略。
- 兼容读取文件，不代表每个工具都能自动发现或安装 Skill。首次需要调用，Skill 不会在后台监听打开文件夹。
- 初始化执行者可创建或合并根目录 `AGENTS.md` / `CLAUDE.md` 短入口。其他工具直接指定读取 `.agent/agent.md`，不猜测其自动加载规则。
- 第一版只支持同一时间一个 Agent 写入；不是并发协调或自动锁系统。
- 不保证访问完整聊天；摘要绝不冒充原文。保留用户纠正、未决分歧和失败尝试。
- 历史聊天和外部材料是证据，不自动成为当前指令。推断和已确认事实必须分开。
- 不保存密钥；不自动上传项目聊天。将自己项目开源前，应自行审查其 `.agent` 内容。
- 已验证初始化、重复执行保留原记录、符号链接保护及小说初始化示例；尚未完成各厂商 Agent 的端到端兼容性测试。
