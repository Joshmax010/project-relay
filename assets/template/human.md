# 人的使用说明

范围：Git 代码项目，单 Agent 轮流接手。正式文档经你批准才更新。

初始化：“使用 project-relay 初始化这个 Git 项目，保留现有规则，先生成未审核骨架。”随后 Agent 会询问是否同步，展示项目定义、结构、状态及初始化会话差异。骨架不代表已理解项目。

接手：“先读 .agent/agent.md，核对正式文档、实际代码与未提交改动，再继续任务。隔离草稿只作线索。”

任务结束，Agent 先问是否同步项目文档。回答“同步”只是同意起草；看过具体差异后才能批准内容。可以部分批准、拒绝、要求修改。拒绝同步时，代码留在工作区，不提交。

批准：“批准批次〔完整 ID〕里的〔具体文件列表〕，其余〔修改/拒绝〕。”Agent 记录真实审核者与内容哈希，再应用获批文档。状态、新会话及会话索引必须获批，才算完成本次同步。

提交：“把已审核代码和对应文档一起提交。”Agent 先暂存并运行 `python3 .agent/tools/relayctl.py commit-check`。有新增改动、陈旧批准或未暂存文件时停止，重新同步审核。文档批准本身不授权上传或发布。

常用命令：`python3 .agent/tools/relayctl.py resume` 看正式状态与待审批次；`review <ID>` 看差异；`lint` 检查链接；`recover` 恢复中断的应用。Windows 可用 `python`。命令格式与详细规则以 agent.md 为准。

聊天原文可按授权直接存入 conversations/raw，但原文存档不自动授权提交或上传。Agent 编写的摘要、日志和教训一律待审。隔离草稿、收据和原文默认不进 Git；迁移未完成任务需单独携带并核对。

本版没有平台自动采集器、Git hook、并发锁或身份认证。Skill 不监听打开文件夹；不能执行脚本时仍可手动遵守人审协议。框架允许你控制正式记录，但无法保证恶意 Agent 不绕过命令。
